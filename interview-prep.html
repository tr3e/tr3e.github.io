PERM 三个设计

PERM 是给 PE 模型的 RL 提供奖励的多维 rubrics 奖励模型。链路：用户 prompt → PE 改写 → 生成视频 → PERM 多维打分 → 聚合成标量 → GRPO 更新 PE。

① 不存在大而全的 rubric，按维度性质路由

通用静态 rubric 的判别力接近随机。所以按性质拆成三种范式：

类型范式为什么必须这样
推理型
指令遵循		长 CoT + 实例级检查清单需要"拆解要求 → 逐条核验"的推理链
主观感知
运动 / 美感		no-think + score-token 软分拆不出客观条件，而且长 CoT 会让打分 token 概率坍缩，直接丢分辨率
客观缺陷
削波 / 杂音		CPU DSP 规则算子有确定性物理信号，程序化比 VLM 更准且零 serving

顺带一句成本设计：按 (范式, 领域, rubric) 分组调用，成本是组数的函数不是 head 数的函数——一次长 CoT 同时产出 5 个指令遵循维度的分。

② 软分：为什么 no-think 是被逼出来的

E[score] = Σ_k k · P(k)     合法数字上重归一

两个视频 argmax 都是 3，完全无法区分；软分能区分 3.438 > 3.349，这个概率质量偏向在 pair 比较里就是有效排序信号。而长 CoT 会把打分 token 概率压到 argmax≈1.0，软分退化成硬分。所以"感知维度用 no-think"不是随便选的，是软分机制的前提。

③ 统计强项 ≠ 正向权重

角色（quality / constraint / monitor）按语义冻结，权重按可靠性给：w = max(0, ROC-AUC 的 case-cluster CI95 下界 − 0.5)。三个能体现判断力的实例：

  • reference_consistency AUC 0.662，判别力中上，但设成 constraint、正向权重 0。因为它语义上是底线不是越高越好——给正向权重的话模型会学会过度保守来刷分。
  • aesthetic_visual 点估计 0.575 看着还行，但 CI95 下界没过 0.5，权重直接是 0。用下界不用点估计，意味着证据不足的维度自动出局。
  • edit_consistency 有 1377 对样本（全场最多），AUC 仍只有 0.513。这不是估计不准，是真没信号——该去重写 rubric，不是去买标注。

④ Essential Gate：核心要求是门，不是加权项

一个 core (P00) 要求未满足，该子维度硬封顶 1-2 分，多少次要点满足都买不回来；且子维度间独立，content_following 的 core miss 不能被优秀的 visual_following 补偿。

一句话说清它的价值

"它避免了核心意图跑偏的样本，因为次要维度表现好而拿到中等偏上评价。对 RL 来说，一个方向错误的正奖励比没有奖励危害大得多。"

u       = sigmoid(α·(raw − center))      α 由无截距 pairwise logistic 对人工 GSB pair 拟合

penalty = −1.0 · Σ max(0, tau_d − u_d)   constraint 头，hinge

★ 决策一：为什么 PPO 换成 GRPO

整个 RL 部分按两个决策讲：先定算法（本节）→ 再定多维 reward 怎么进 advantage（下一节）。顺序别倒，倒了听的人会不知道你在哪一层做取舍。

PPO 在视频 reward 上的两个致命伤

  1. Critic 几乎训不好。value 网络要从当前 state 预测最终视频会被 RM 打多少分，但这个回归目标同时满足了所有最难的条件：奖励是终局的（视频全部生成完才有分，中间步骤没有可靠的信用分配信号）、值域混乱（多维分聚合后的标量分布本身随训练漂）、目标非平稳（RM 还在迭代版本，换版本就整体平移）、样本极贵（每个样本要真跑一遍视频生成加多次 VLM 打分，critic 想收敛需要的数据量根本喂不起）。Critic 拟合不好，advantage 就是噪声，PPO 的低方差优势直接不成立。
  2. 显存爆炸。PPO 要同时持有 policy / ref / reward / critic 四份模型，critic 通常和 policy 同量级。视频生成这边本来就 DiT + VAE + text encoder 堆满了，再加一个同量级 critic 直接翻倍。

GRPO 怎么正好命中这个任务

核心动作只有一个：同一个 prompt 采一组样本，用组内相对比较当基线，把 Critic 整个砍掉。四个任务特性逐一对上：

视频任务特性GRPO 为什么不吃亏
序列级 / 终局奖励本来就是对整条轨迹给一个标量优势，不需要 per-token value——正好匹配"只有终局有分"
延迟奖励没有中间信用分配的需求，组内比较直接给出"这个样本比同组平均好多少"
值域混乱组内归一化把任意值域映射成相对排序，不需要谁去学绝对值域
多维度 reward组内相对比较天然消掉各维度的绝对偏置（这条直接通向决策二）
一个能加分的二阶效应

砍掉 critic 省下的显存不是白省的——它直接换成更大的 group size G，而 G 越大组内基线估计越准。省显存和降方差在这里是同一个动作的两面，形成正反馈。这点主动讲出来，比只说"省显存"高一档。

务必带上这个 caveat，否则像在跟风

"GRPO 不是无条件比 PPO 强。在奖励稠密可靠、值域稳定、采样便宜的任务上，训得好的 critic 能给出比组内均值更低方差的基线，GRPO 反而是更粗糙的估计，而且要付 G 倍的采样成本。是视频生成这个任务把 PPO 的固有缺陷放大了——奖励终局、非平稳、多维、样本极贵、模型极大——而 GRPO 恰好这几条都不吃亏。所以这是任务特性和算法特性对上了，不是算法本身更先进。"

★ 决策二：为什么 advantage 加权而非 reward 加权

结论先行

确定用 GRPO 之后，多维 reward 还剩一个聚合位置的选择：先加权成标量再算组内 advantage，还是逐维各算组内 advantage 再加权。线上是后者。一句话理由：raw 加权实际施加的权重是 w_d·σ_d 而不是你配置的 w_d，而 σ_d 你控制不了。

文档待更新

脱敏文档 §1.4 / §3.2 现在还写着 use_subdim_grpo=False / scalar-GRPO，和线上实际不一致。面试前记得改掉，否则被问到时自己的材料和口径会打架。

骨架：一个恒等式

A：raw 加权成标量再算 advantage              B：逐维 advantage 再加权（线上）
s_i = Σ_d w_d·u_{i,d} / W                    A_{i,d} = (u_{i,d} − ū_d) / σ_d
A_i = (s_i − s̄) / σ_s                        A_i     = Σ_d w_d·A_{i,d} / W

把 A 展开，代入 u_{i,d} − ū_d = σ_d·A_{i,d}：

A_i = Σ_d [ w_d·σ_d / (W·σ_s) ] · A_{i,d}
题眼

两者都是线性组合，只差系数。raw 加权实际施加的权重是 w_d·σ_d，不是 w_d。而 σ_d 是组内标准差，取决于当前策略和当前 prompt，根本不是你能配置的量。

后果一：标定出来的权重直接失效

用你自己的 R2V 权重量化一下。假设 PE 的指令遵循已经练得很好所以组内几乎不波动，而生动度波动大：

head配置占比σ_d 假设w·σ实际生效偏移
task_response65.4%0.030.019630.0%−35.4pt
motion_vividness9.0%0.200.018027.5%+18.5pt
audio_expressiveness14.6%0.100.014622.3%+7.7pt
motion_quality11.0%0.120.013220.2%+9.2pt

设计上让 task_response 扛三分之二，实际梯度里只占 30%；只给 9% 的 motion_vividness 实际占 27.5%，放大三倍。你花在标定权重上的所有功夫，在这一步被 σ_d 悄悄改写了。

σ_d 是为说明问题假设的，讲的时候要注明不是实测。

后果二：训练中分布漂移，目标函数自己走偏

上面还只是某一时刻的静态偏差。更麻烦的是各维度的分数分布在训练中根本不是静止的，而 raw 加权下 σ_d 的任何变化都会直接改写实际权重：

  • 简单维度先饱和：指令遵循通常最先练到天花板，组内 σ 迅速趋近 0，于是它自动退出梯度。
  • 难维度长期保持方差：美感、运动质量收敛慢，σ 一直不小，于是它们接管了梯度。
  • RM 自身在迭代版本：换一版 RM，各维度的值域和方差整体平移，实际权重跟着跳变。
由此产生的典型失效模式

训练早期指令遵循贡献最大，中后期它饱和退出、梯度被感知维度接管，于是模型开始在指令遵循上缓慢退化——因为已经没有梯度在维持它了。表现出来就是"练着练着指令遵循掉了，但没人动过配置"。这类问题极难归因，因为配置文件从头到尾没变过。

逐维归一化下，只要某维度在组内还有任何排序信息，它就以配置权重参与更新，不会因为绝对差值变小而被淹没。当然它真的完全无区分度时谁也救不了——那种情况任何方案都没有信号可用，也正是需要下面第一条对策兜底的原因。

逐维不是免费的：三个代价，以及怎么接住

光说"逐维更忠实于配置"是半个答案。能主动讲出代价和对策，才是把这题答满的地方——面试官几乎一定会往这里挖。

  1. 低方差维度的噪声被放大到满权重。如果一组样本美感确实一样好，σ≈0，逐维 z-score 等于除以一个基本由噪声构成的数，把纯噪声放大回配置权重，模型于是学会拟合噪声。
    对策就是你们已有的那道门：权重按 ROC-AUC 的 CI95 下界给，不过下界就是 0 权重。这道门在标量方案下只是稳健性措施，在逐维方案下是前置必要条件——没有它不敢上 subdim。aesthetic_visual（点估计 0.575、下界没过 0.5、权重 0）就是这道门在真实生效的例子。工程上再加个方差地板 max(σ_d, ε) 兜底。
  2. 非线性项没法分解。penalty = −λ·Σ max(0, tau_d − u_d) 是 hinge，外面还有 clip，而 Σ_d w_d A_d 预设了聚合对各维度线性。更要命的是语义：对 constraint 头做组内 z-score，等于把"门"变成"排序信号"——永远要比同组更好，这正是把它们设成 constraint、正向权重给 0 想关掉的 hacking 面。
    所以合理的形态是混合：quality 头走逐维 advantage，constraint penalty 仍施加在标量上，保住 gate 语义。这块确认一下你们线上具体怎么处理的，我只能从公式形态推断。
  3. 逐维 N/A 会打碎组内统计。纯 T2V 时 reference_consistency=na，head 也可能 fail，于是每个维度的 mean/σ 要在组内不同子集上算、n 还各不相同。G=8 时某维度只在 2 个样本有效，用 n=2 估出来的 σ 去做除法很危险。
    对策：有效样本数低于阈值时该维度直接退出本组的 advantage（等价于当次权重归零），而不是硬算一个 σ。
收口：一句话讲清取舍 + 该有的监控

"两种做法都是各维度中心化值的线性组合，只差系数。raw 加权尊重'这个维度这次有没有区分度'，但你失去了对配置的控制权；逐维 advantage 忠实于配置，代价是要自己负责把没信号的维度挡在门外。我们选逐维，是因为权重是用 ROC-AUC 置信下界推出来的——既然权重本身是个无量纲的可靠性量，就该施加在同样无量纲的 advantage 空间里，施加在 raw 空间会把量纲依赖又请回来。"

配套监控：每步记录 w_d·σ_d / Σ_e w_e σ_e，即"如果走 raw 加权会生效的权重"，和配置权重做对比。几乎零成本，能直接量化逐维方案到底纠正了多大的偏移，也是回答"这个改动有多大收益"的证据。

深挖追问

那把 w_d 调大去补偿 σ_d 不就行了？

不行，σ_d 非平稳而且是 per-prompt 的。训练中各维度饱和速度不同，你调的是移动靶；不同 prompt 的 σ_d 分布也不一样，没有任何一组常数能同时补偿所有 group。补偿 σ_d 本质上就是在做逐维归一化，只是用手动、滞后、且只在均值意义上正确的方式做。

GRPO 里除以 std 本身不是有偏吗？（考察 Dr.GRPO）

问得很准，这是我们方案最实在的一处代价，不要回避。

"是的，除以组内 std 会引入难度偏置——组内方差小的 prompt 梯度被放大，相当于加了个和难度相关的隐式权重。而且这个批评对逐维版本比对标量版本更尖锐，因为我们把这个有偏的除法做了 D 次。

关键是要把两件常被混谈的事分开：逐维中心化是无偏的方差缩减，除以组内 std 才是引入偏置的那一步。我们真正需要的是前者——去掉每个维度、每个 prompt 的基线；后者只是为了让权重可比。所以自然的收敛方向是保留逐维中心化，但把分母从组内 σ_d 换成跨 batch 的 EMA 全局 σ_d：既拿到权重忠实性，又不吃组内 std 的难度偏置和小样本噪声。"

逐维 advantage 会不会反而加剧 reward hacking？

会，这是我们上逐维时最先要堵的口子，坦诚承认再讲对策。

"逐维归一化保证每个维度永远以满权重推动策略，包括判别力接近随机的那些。raw 加权下没信号的维度会自然沉默，逐维会强行把它的噪声放大到配置权重，模型于是学会拟合噪声。

所以这两个设计是配套的、不能拆开看——AUC 的 CI 下界门控在标量方案下只是个稳健性措施，在逐维方案下它是前置必要条件。正因为我们先有了'不过 CI 下界就是 0 权重'这道门，把没证据的维度整个挡在 advantage 之外，逐维归一化才是安全的。反过来说，如果哪天有人想放宽权重门槛，那必须先把逐维换回标量。"

group size G 怎么定？

G 是基线估计质量和采样成本的直接权衡，而视频生成里每个样本都要真跑一遍生成加打分，所以这个权衡比文本 RL 尖锐得多。

两个约束一起看：G 太小组内均值噪声大、基线不可靠（而且逐维 σ̂ 更不可靠——G=8 时相对误差就有约 25%）；G 太大则每个 prompt 的边际收益递减，不如把算力铺到更多 prompt 上去覆盖分布。砍掉 critic 省下的显存正好换成更大的 G，这是选 GRPO 的一个附带收益。

只有一笔人工标注预算，花在哪？

花在判别力已证明"中等"、但样本量还撑不起 CI 下界的维度上，别均匀铺。aesthetic_visual（0.575 / n=353，下界没过 0.5）是最典型的"可能有信号但证据不足"，边际收益最高。反过来 edit_consistency 已经 1377 对还是 0.513，那是 rubric 设计问题不是数据量问题，再买标注也救不回来。
